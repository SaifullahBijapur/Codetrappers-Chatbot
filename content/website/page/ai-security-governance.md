1.  ### Inventory what is actually connected

    Most organisations underestimate this. Assistants added to a helpdesk, an API key in an automation tool, a plugin someone installed. The list is longer than the one anybody remembers.

2.  ### Reduce every credential to least privilege

    Integrations are usually built with an admin token because that made the first demo work. Each one gets scoped down to the capabilities it genuinely needs.

3.  ### Log every call in a form a person can read

    Which tool, which arguments, whose credentials, what changed. This is the difference between an incident you can explain and one you cannot.

4.  ### Test what happens with hostile input

    Instructions hidden in a web page, a support ticket or an uploaded document are the current attack. We try them against your setup rather than assuming the model resists.

5.  ### Write a policy people can actually follow

    Which tools are approved, what data may go into them, who signs off a new one, and what happens when something goes wrong. Short enough to be read.

## The failures we see most

None of these are exotic. All of them are common.

### One over-permissioned key doing everything

Created for a proof of concept, never scoped down, now in production and shared between three tools.

### Tool output trusted as instruction

An agent that treats text from a scraped page or a customer ticket as a command can be steered by anyone able to write into that system.

### A policy that describes a different site

Analytics and advertising loading before consent while the policy says otherwise is the single most common finding, and one of the easiest to fix.
